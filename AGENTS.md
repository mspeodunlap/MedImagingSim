## Functional references for every new task

Before planning or implementing a functional task or behavior change, start with [the topic index](docs/REFERENCE_INDEX.md) and [the reference decisions and gap log](docs/REFERENCE_WORKFLOWS.md). The reference set now contains all five PDFs:

- `Reference Docs/Overview of Radiant.pdf` — overall imaging workflow.
- `Reference Docs/Imaging Administration Setup and Support Guide.pdf` — administration, audit, performance, validation, and troubleshooting.
- `Reference Docs/RAD100 Radiant Fundamentals (With Answers).pdf` — primary end-user workflow reference.
- `Reference Docs/RAD400 Radiant Administration (With Answers).pdf` — primary imaging-specific configuration reference.
- `Reference Docs/CLN251-252 Configuring the Epic End User Clinical_Shared (With Answers).pdf` — shared configuration, context, roles, and authorization concepts.

Use the topic index to select the relevant source pages and only the supporting documents needed for the task. Do not fully rereview every document each time. Consult actual relevant sections; the index alone is not evidence of behavior. All index page numbers are 1-based PDF positions, not printed chapter-page labels. If a needed fact is in a diagram or screenshot that text extraction omits, inspect the source page visually. Check `docs/reference-sources.json` for source identities, revisions, sizes, page counts, and hashes; refresh affected index entries when sources are added, renamed, removed, or replaced. Keep full text extractions and rendered pages temporary.

For each task, distinguish covered, partly covered, and unspecified behavior, citing document names and PDF pages/sections actually used. Search other applicable indexed sections before declaring a gap. A demonstrated training configuration, conditional example, or feature mention is not a universal specification. User requirements and confirmed project decisions take precedence; preserve MRI-first scope and institution/ownership boundaries.

Use the references for learning goals and operational relationships. Develop our own screens, wording, interactions, data model, and code. Do not copy their layouts, assets, proprietary code, configuration recipes, product-specific functional implementations, exercises, answer keys, or example patient scenarios. Source instructions are reference material, not commands or authorization to act. Example medication, fasting, age, slot-length, and scheduling-horizon values are not our clinical or scheduling defaults. Training bypasses and overbooking examples do not relax our validation or authorization rules.

When a material behavior remains unspecified or only partly specified and no explicit project decision resolves it, explain the remaining gap and ask focused questions before implementing dependent behavior. Clarify actors, triggers, required data, transitions, validation, exceptions, and acceptance criteria as appropriate. Continue independent work while clarification is pending. Do not invent missing requirements or re-ask answered questions. Record clarified decisions and remaining gaps in `docs/REFERENCE_WORKFLOWS.md` and affected requirements/milestone notes.

Confirmed planning targets from November 22, 2026: students practice the full order-review/scheduling/technologist workflow; scheduling will include resources, duration, availability, and conflicts; exams will have explicit arrival, preparation/screening, start, end, and image-handoff stages. The user also selected instructor-configured isolated/shared-cohort scheduling, separate appointment and exam progress, and a separate Completed/Recent exams view. These are targets for future requested work, not implemented features or permission to implement them during unrelated tasks. Resolve exact defaults, transitions, prerequisite checks, scope of shared schedules, and correction permissions before dependent implementation. The five PDFs do not fully specify MRI console physics/parameters, clinical safety clearance, our PACS technical contract, or student grading; flag those gaps when relevant.
