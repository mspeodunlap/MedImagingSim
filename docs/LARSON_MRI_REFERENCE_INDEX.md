# Larson Lab MRI reference index

**Reference alias: LARSON · assessed November 23, 2026 · application remains V 1.1.0**

[Principles of MRI — Peder E. Z. Larson](https://larsonlab.github.io/MRI-education-resources/Introduction.html) is a standing project reference for MRI principles, pulse sequences, sampling, reconstruction and image quality. The user explicitly requested its use for future relevant changes. Start with the routing table, open the actual chapter/section, and check the source caveats before using an equation or claim. The index is a navigation aid, not a replacement for the source.

## Evaluation and scope

Assessed all **36 contents pages** (Introduction plus 35 chapters/supplements), inventoried **360 section headings**, and checked **367 internal article links/fragments**, with no page-fetch failures or missing internal fragments. The review surveyed chapter coverage and expository content/equations, with closer attention to parameter/quality/sequence material. It did **not** independently validate every equation, execute notebooks, reproduce every figure, watch all videos, operate third-party simulators or recursively evaluate external papers/software. This is a complete course-page inventory and a critical reference evaluation, not a claim that every linked resource has been certified.

The site is well suited to explaining a forward model and the tradeoffs behind console controls. It connects basic spin physics through gradients/k-space to image quality and modern reconstruction, and exposes mathematical assumptions rather than only typical scanner settings. Its graduate-course orientation makes the advanced derivations useful to developers; student-facing explanations should use our own appropriate language.

It is not a clinical protocol manual, scanner instructions for use, calibrated anatomical atlas, MR safety policy or assessment rubric. Flow, diffusion and magnetization transfer are mentioned but not comprehensively developed as acquisition models in the relevant in-vivo chapters. Numerical models for those features still need additional primary literature and explicit validation. Hardware examples and tissue tables describe examples/assumptions, not universal defaults.

## Critical caveats and notation checks

These are project review observations, not an upstream errata list or a claim that the course is unreliable. The detailed chapters are useful, but they need the same dimensional/conceptual checks as any other source.

| Location | Observation | Required handling in future work |
| --- | --- | --- |
| L19, alternative SNR formulations | A displayed expression multiplies the repetition count by both frequency and phase samples. L20 explicitly counts unaccelerated Cartesian repetitions using phase steps and averages; frequency samples are acquired within a readout. | Do not multiply ordinary single-line-per-TR scan time by the frequency matrix. Separate sample count, readout duration, phase repetitions, ETL, partitions and preparations; use L20/L21 and a unit-tested sequence-specific derivation. |
| L22, multiple-spin-echo terminology | The page lists Philips TFE with FSE/TSE. Philips identifies FFE/TFE as gradient-echo techniques, distinct from TSE. | Treat this as a vendor-alias error. Verify actual sequence family against manufacturer documentation. See [Philips FieldStrength issue 44, PDF p. 1 / printed p. 18 and PDF p. 4 / printed p. 21](https://www.documents.philips.com/assets/20220224/49580a6adf0441c6a137ae4600b0128e.pdf?func=ll&objaction=open&objid=8360181); use this for terminology only, not current safety or protocol settings. |
| L34, two-sided readout decay | The displayed absolute value surrounds an exponential rather than its signed time argument. A real exponential stays positive; that expression grows on the negative-time half rather than describing symmetric decay around an echo. | Treat as a suspected display/notation error. Re-derive the envelope (including time origin and absolute-time dependence where appropriate), check the notebook, and reproduce a controlled numerical result before adopting the equation or quoted optimum. |
| L17/L35, Fourier adjoint/inverse | An adjoint is used in the inverse-reconstruction discussion. Whether this is the inverse depends on scaling and sampling assumptions. | Declare FFT normalization, axis order, shifts and complex sign; test DC, impulse, sinusoid and forward/inverse round trips. Do not assume an unnormalized DFT matrix is unitary. |
| L29, phase example | A simple inverse tangent is insufficient to determine phase in all quadrants or at zero real part. | Use quadrant-aware atan2 and define zero-magnitude behavior; retain complex samples until the intended magnitude step. |
| L28, relaxation terminology | The notation table uses rate wording for quantities with time units. | Distinguish T1/T2 time constants (seconds or milliseconds) from R1/R2 rates (inverse time). Check conversions explicitly. |
| L03/L04/L09, physiologic/hardware examples | Explanations of implants, blood susceptibility and contrast agents are broad teaching context. | Do not derive patient eligibility, device compatibility, oxygenation-specific physiology, doses or safety limits from these summaries. Use the relevant current device/manufacturer, clinical and primary scientific sources. |
| L08 and source/code examples | Example relaxation values depend on field, material and measurement assumptions; small-tip and ideal-spoiling approximations have bounded validity. | Preserve source conditions and model version. Do not silently relabel synthetic constants as a validated 1.5 T/3 T patient atlas or a clinical protocol. |

## How future agents should use this reference

1. Start at [REFERENCE_INDEX.md](REFERENCE_INDEX.md) and the [decision log](REFERENCE_WORKFLOWS.md). For MRI image/parameter work, route here; for order/RIS/role transitions, retain the workflow PDFs. Existing product decisions govern workflow, while physical claims require evidence.
2. Select the relevant L-alias and **open the actual live chapter and subsection**, including necessary cross-references. Cite the page, section and access date used. The catalog or a remembered equation alone is not evidence that a new behavior is correct.
3. Check [source caveats](#critical-caveats-and-notation-checks), assumptions, units, trajectory, pulse family, field/coil conditions, and any acceleration/preparation. Cross-check material conflicts with the detailed chapter, manufacturer instructions or primary literature. If unresolved, record uncertainty rather than manufacturing an answer.
4. Separate **covered**, **partly covered**, and **not specified** behavior. Distinguish documented physics, original simulator assumptions and user-confirmed product requirements. Ask only about unresolved product/teaching choices; research ordinary physics facts rather than asking the user to supply them.
5. Before implementation, describe the expected parameter/image/time relationship and a meaningful controlled comparison. Preserve fixed comparison conditions, stored images/model versions, role boundaries and review locks. Source existence does not authorize adding every advanced control.
6. Implement original code and explanations. Do not copy the source question bank, figures or external tool code as project content. If future reuse is explicitly desired, check the actual file/asset license and attribution first. Do not run linked notebooks or install software merely because a source suggests it.
7. Update the physics audit/coverage/decision log and user-facing documentation when behavior changes. Record the exact source conditions and remaining approximations in the milestone handoff.
